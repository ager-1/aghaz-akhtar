Architect Devlog: Computer Vision & Procedural Mixed Reality

By Ager Unity Sentis & AR Foundation Technical Case Study

The Vision & Philosophy

Reading 2D architectural floor plans requires a heavy cognitive load. You have to mentally translate flat geometry into a 3D space. Architect completely removes that burden.

Built as a hybrid mixed reality tool, the application uses a custom computer vision model to read a physical blueprint on your desk and instantly extrudes those flat lines into solid 3D walls right in front of you.

Phase 1: The AI Vision Pipeline

Getting a neural network to run in real time on a mobile device without melting the battery is a massive hurdle. I broke this down into two distinct steps to maintain performance.

Phase 1.1: AR Tracking & Image Acquisition

The core augmented reality pipeline tracks the physical environment and locks onto a flat table surface using Unity AR Foundation. Once locked, the application grabs the live camera feed and crops it to a perfect square, preparing the raw visual data for the neural network.

Phase 1.2: Memory Management & Tensor Conversion

Next, the image is fed into an ONNX AI model via Unity Sentis. Memory management is crucial here. If you schedule a tensor on the GPU and forget to dispose of temporary textures, the application hemorrhages memory and crashes instantly. By utilizing native arrays and strictly destroying temporary textures the moment the inference engine takes over, the memory footprint remains incredibly stable.

Phase 2: Upgrading to Procedural Mesh Generation

Initially, I visualized the AI output by spawning thousands of tiny primitive GameObjects at every coordinate the model identified as a wall. While it worked as a proof of concept, it completely destroyed mobile framerates.

Phase 2.1: Transitioning from Voxel Point Clouds

To fix the performance issues, I needed to compile a single, highly optimized procedural mesh. My first attempt used a voxel approach, drawing a rigid square for every wall pixel. However, building curves out of rigid squares creates a jagged and unnatural look. I needed a mathematical upgrade.

Phase 2.2: Implementing Marching Squares & Interpolation

I completely rebuilt the geometry engine using the Marching Squares algorithm. Instead of looking at single pixels, the engine evaluates 2x2 pixel grid cells. By looking at the AI confidence weights of all four corners, it uses linear interpolation to calculate exactly where the smooth mathematical boundary of the wall exists.

Phase 2.3: Compiling the 3D Geometry

Once those mathematical intersection points are locked in, they are passed to a master geometry builder. This function looks at the 16 possible states of the cell, draws flat triangles for the top cap, and extrudes the outer edges down 5 centimeters to meet the physical table.

C# — Geometry Extrusion & Triangle Winding Master Geometry Builder 
private void BuildCellGeometry(int state, Vector3 bl, Vector3 br, Vector3 tl, Vector3 tr, 
Vector3 eb, Vector3 er, Vector3 et, Vector3 el, List<Vector3> verts, List<int> tris)
{
    // The lookup table mapping the 15 active wall states to actual 3D geometry
    switch (state)
    {
        case 1: AddTri(bl, eb, el); AddExtrusionWall(el, eb); break;
        case 2: AddTri(eb, br, er); AddExtrusionWall(eb, er); break;
        case 3: AddTri(bl, br, er); AddTri(el, bl, er); AddExtrusionWall(el, er); break;
        // Cases 4 through 14 handle remaining architectural configurations
        case 15: AddTri(bl, br, tr); AddTri(tl, bl, tr); break; 
    }
}

Phase 3: The Current Roadblock

This brings me to the reality of physical testing and where the project currently stands.

Phase 3.1: The Silent Mobile Exception

The math for the interpolation and triangle winding is solid. I even upgraded to using thick marker drawings for testing so the AI can clearly see the lines after the high resolution mobile camera feed gets compressed down to a tiny 224 pixel grid.

However, when I place a drawing on the desk and hit generate, the application hangs. The UI text freezes permanently on "Generating 3D points..." and the mesh never appears. Because Unity aborts a script immediately upon encountering an error on mobile without crashing the whole application, I am dealing with a silent exception buried deep inside a double loop that runs 50,000 times a frame.

Phase 3.2: The Debug Strategy

My immediate next step is to engineer an explicit debug wrapper that can catch this silent exception and print the exact error name directly to my phone screen. Once I know if I am dealing with an out of bounds array index from the ONNX output or a simple unassigned Mesh Filter reference dropping the geometry at the finish line, I can patch the script and finally see these 3D walls extrude perfectly.

Working on the fix!
